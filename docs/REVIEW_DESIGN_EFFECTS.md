# DESIGN_EFFECTS.md 設計書レビューレポート

## 概要

本ドキュメントは、設計書 `DESIGN_EFFECTS.md` (Spiral Suction Saver 拡張設計書: レイヤー分離エフェクトシステム) に対する詳細レビュー結果および指摘事項をまとめたものです。

全体として、本設計書は要件の構造化、モジュール設計、幾何・数式モデル、GL 1.1 描画パイプライン、状態遷移機械、テスト方針、性能予算、および既存実装との互換性（付録A含む）に至るまで極めて高度かつ緻密に詳細化されています。設計の多くが「第三者が読んでも実装可能」という目標を高い水準で達成しています。

本レビューでは、実装時の不具合防止・エッジケース対応・マルチスレッド安全性の向上を目的とし、以下の通り指摘事項を抽出し、重要度（Major / Minor）を評価・記録しました。

## 各指摘事項の詳細

### ISSUE-1 [Major]: `HueRingBuilder` ワーカースレッドのライフサイクル管理と再初期化・破棄の設計不足

- **該当箇所**: §3.2 (src/platform/win32/), §6.2.8 (HueShift), §7.4 (テクスチャ準備)
- **問題点**:
  色相サイクル (`HueShift`) 用のテクスチャ生成スレッド `HueRingBuilder` は、`std::thread` を使用して CPU で色相回転画像を事前生成する設計となっています。
  しかし、以下のケースにおけるスレッド制御が記載されていません：
  1. セーバー終了時にスレッドがまだ実行中である場合のキャンセル / `join` 処理。
  2. 設定変更やスクリーン解像度変更等により `AppController::Initialize()` が再呼び出しされた際、既存スレッドの安全な停止および未完了タスクの破棄手続き。
  3. ワーカースレッドから主スレッド（`AppController`）への生成済み RGBA バッファ受け渡しにおける排他制御（ミューテックス、アトミックフラグ、所有権移動等）の具体的データ構造。
- **推奨改善案**:
  `HueRingBuilder` クラスのインターフェースに `Stop()` / `Join()` / `IsRunning()` および排他制御用の `std::mutex` / `std::atomic<bool>` による状態管理を明記してください。

### ISSUE-2 [Major]: 上物レイヤーにおける `Tiles` (複製描画) の全画面クアッド後処理とフィルレート/幾何一致性

- **該当箇所**: §4.3 ( GeometryKind ), §6.1.3 (InfiniteScroll), §6.1.4 (InfiniteRotation), §7.5 (1フレームのGL呼び出し回数)
- **問題点**:
  §7.5 において、上物のセル数が `tileCellLimit (=4000)` を超える場合、`EffectEngine` が「各複製オフセットについて全画面クアッド 1 枚に後処理でまとめる」最適化を行うと規定されています。
  しかし：
  1. 上物レイヤーの全画面クアッド描画は、差分なしピクセル（アルファ 0）も含めて画面全域のクアッドを描くため、`InfiniteRotation` 等で可視複製数が 4〜6 枚ある場合、フィルレート（オーバードロー）が急増します。
  2. 個々のセルクアッド群（UV が各セルの範囲）から全画面クアッド 1 枚（UV が $(0,0)$〜$(1,1)$）へ差し替える際、複製オフセットの適用軸やテクスチャの端の折り返し処理の幾何学的整合性が $IEffect$ の数式と完全に一致するかどうかの詳細定義が不足しています。
- **推奨改善案**:
  全画面クアッド化を行った際の UV 座標マッピングの計算式を明記し、フィルレート増加に対する注意書きまたは上限設定を追記してください。

### ISSUE-3 [Major]: `CoverScale` の適用ルールと $I < 1$ 時の背景境界露呈リスクの矛盾

- **該当箇所**: §6.0.4 (CoverScale), §6.2.4 (Tilt), §6.2.10 (ParallaxTilt)
- **問題点**:
  - §6.2.4 (Tilt) の本文中には「`scale` は最大角で固定し、揺れの最中に拡縮が見えないようにする」とある一方で、数式では `scale = 1 + I * (coverScale - 1)` と包絡値 $I$ (0..1) に応じてスケールを変化させる記述があり、文章と数式の間で矛盾が存在します。
  - $I < 1$ （Entering / Exiting フェーズ）かつ回転角 $\theta > 0$ の状態において、`scale < CoverScaleForRotation(W, H, θ)` になると、画面四隅に黒い背景が露出する計算上のリスクが生じます。
- **推奨改善案**:
  回転系・変形系の背景エフェクトにおける `scale` の決定式を「現在角 $\theta(t)$ に対する必要最小限の CoverScale」とするか、「最大角に対する固定 CoverScale」とするかを明確に統一し、$I < 1$ であっても画面端が切れない数式に修整してください。

### ISSUE-4 [Major]: `Mesh` 解像度の再分割 ($s \times s$) 時の `MeshBuilder` インタフェースおよびマッピング定義の不足

- **該当箇所**: §4.4 (Mesh), §4.4.1 (格子メッシュ), §12.3 (test_fx_Mesh)
- **問題点**:
  §4.4.1 で、差分マスクの粒子グリッド `gridN < 48` の時にセルを $s = \lceil 48 / gridN \rceil$ 分割し、`quadActive` を親セルから子クアッド群へコピーする仕様が記述されています。
  しかし、`Mesh` 構造体（§4.4）には `cols`, `rows` しか定義されておらず、親セルインデックスと再分割後のクアッドインデックスを紐付けるデータ構造や、`MeshBuilder::BuildGrid` の関数シグネチャ・引数定義が不完全です。
- **推奨改善案**:
  §4.4 または §4.4.1 に `BuildGrid` の完全な C++ 関数シグネチャおよび、再分割時の頂点インデックス・クアッドインデックス算出式を追記してください。

### ISSUE-5 [Minor]: 継続エフェクト全 OFF 時における上物終端エフェクト発動タイミングの設計確認

- **該当箇所**: §5.2 (共通エフェクト状態機械), §5.3 (ForegroundEffectStateMachine)
- **問題点**:
  ユーザーが上物の継続エフェクトを全て OFF にし、特定の終端エフェクト（例: `GlassShatter`）のみを ON に設定した場合、`NoCandidatePolicy::ImmediateTerminal` により `Reset()` 直後に `TerminalRunning` へ移行します。
  この結果、セーバー開始直後（0 秒時点）に終端エフェクトが即座に発動して上物が消滅することになります。ショーケース時間（既定 40 秒）静止状態を維持した後に終端エフェクトへ入る挙動を期待するユーザーも考えられるため、設計意図の確認が望まれます。
- **推奨改善案**:
  継続エフェクト 0 件時の動作仕様（「ショーケース時間なしで直ちに終端発動」）が意図通りの仕様であることを明確に注記してください。

### ISSUE-6 [Minor]: `MosaicCollapse` および `GlassShatter` における遅延時間中 ($\tau < 0$) の状態明記

- **該当箇所**: §6.1.9 (GlassShatter), §6.1.11 (MosaicCollapse)
- **問題点**:
  `FragmentSystem` で個々の断片が遅延時間 `delay` を持つ場合、落下・飛散開始前 ($\tau = t - delay < 0$) の間の位置・回転・スケールの状態が、各積分器の擬似コード上で明示的に早期リターンされる記述になっていません（`GlassShatter` ではひび割れ閃光の処理が記載されていますが、`MosaicCollapse` 等では簡略化されています）。
- **推奨改善案**:
  `FragmentSystem` の共通挙動として「$\tau < 0$ の断片は $restPos$, $rot=0$, $scale=1$ の静止状態を維持する」旨を明記してください。

---

### ISSUE-7 [Minor]: `GlitchShift` RGB 分離 3 パス描画におけるアルファチャンネル書き込みマスクの扱い

- **該当箇所**: §6.2.9 (GlitchShift), §7.2 (Renderer::ExecuteDrawList)
- **問題点**:
  §7.2 の `ExecuteDrawList` では `glColorMask(batch.colorMask.r, .g, .b, GL_TRUE)` とアルファチャンネルの書き込みが常に有効化されています。
  背景描画（不透明）においては問題ありませんが、RGBの分離パス（Rのみ、Gのみ、Bのみ）を順次描画する際、アルファ値が重ね書きされる挙動についての考慮事項を注記しておくと安全です。
- **推奨改善案**:
  背景描画バッチにおけるアルファ値が常に 1.0 であるため問題ない旨を §7.2 または §6.2.9 に注記してください。

---

### ISSUE-8 [Minor]: エフェクト単位の設定値パースにおける 0 値と `Min > Max` 判定の優先順序の明確化

- **該当箇所**: §9.2 (キー仕様)
- **問題点**:
  §9.2 において、エフェクト単位の `MinSeconds` / `MaxSeconds` で「どちらか一方でも 0 なら両方層既定値を使う」ルールと、「`Min > Max` の場合」のパース判定が記載されています。実装時の処理順序（0 判定を先に行うか、`Min > Max` 判定を先に行うか）を明記しておくと、実装者による揺れを防ぐことができます。
- **推奨改善案**:
  パースロジックの評価順序（1. 0 判定 → 2. 範囲クランプ → 3. Min > Max 判定）を擬似コード等で明確化してください。
