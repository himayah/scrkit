# ScrViewer の見た目 (採用したデザイン)

> 状態: 採用済み(ブランチ `feature/scrapi-viewer`)。デザイン案の元データ(キャンバス):
> https://claude.ai/artifact/4gS22VghDSjKbTKL1YZXiK (ボード「Windows 11 ライト」が基準)。
> 本書はその案から**実装に必要な決定事項**を書き出したもの。案のキャンバスは作成者(ユーザー)のみ閲覧可。

## 1. 方針

- **基準は Windows 11 ライト**(標準の Windows 11 アプリに近い見た目)。ダークは同じ構造の配色違いとして用意する
  (§3)。macOS / GNOME の案は検討したが、このビュワーは Windows 専用のため**採用しない**。
- 作り込み過ぎず、余白と角丸と 1 色のアクセントだけで整える。装飾(グラデーション、影の多用)はしない。
- 標準部品の見た目調整ではこの案は実現できない(角丸、チップ、ノブ、折りたたみカード、ダーク)。加えて、約 500 個の
  子ウィンドウは起動の遅さ・スクロールのちらつきの原因だった。そのため**コントローラパネルは 1 枚のウィンドウに
  自前で描画する**(Direct2D + DirectWrite、OS 標準で追加依存なし)。
- プレビュー領域(`.scr` を埋め込む子ウィンドウ)だけは標準の子ウィンドウのまま(`/p <hwnd>` の仕組みが必要)。

## 2. 画面構成 (1360 x 940 を基準とした寸法)

```
┌ タイトルバー (OS 標準 32px) ──────────────────────────────────────────┐
│ コマンドバー 48px: [Open screensaver…] [ファイル名 v2.1.0 · SCRAPI 1.0]   (Connected) [↻] │
├──────────────────────────────────────────────┬────────────────────────┤
│ プレビュー (黒地、角丸 8、21:9 を黒帯で収める)   │ 検索 [Filter controls] [Reset all] │
│  左上に "2560 × 1080" "Fit to window" の札      │ ▼ Background        Pin · FadeOutIn │
│                                              │   カード(角丸 8、枠 1px)…   │
│ ┌ 操作バー 52px ────────────────────────────┐ │ ▼ Foreground …             │
│ │ ⏸ ⏭ │ Speed ──●── 1.0× │ Seed [12345] [↻ Restart] │ │ ▼ <Effect> parameters      │
│ └─────────────────────────────────────────┘ │ ▶ Content   ▶ Phase (折りたたみ) │
├──────────────────────────────────────────────┴────────────────────────┤
│ 状態バー 28px: ● Connected: <name> <ver>  Saver started N ms  Handshake N ms  Panel N ms   60 fps │
└─────────────────────────────────────────────────────────────────────────┘
```

- 右パネルは幅 392px(内側の余白 12px、カード同士の間隔 8px)。プレビュー側は残り全部。
- 操作バーの部品は、マニフェストの標準コントロール `scrapi.*`(`paused`/`step`/`timeScale`/`seed`/`restart`)を
  パネルではなくバーに出す。
- 実装は段階的: まず右パネルを自前描画にし(本書 §4-§5)、次にコマンドバー・操作バー・状態バーを載せる。

寸法: 部品の角丸 4、カードの角丸 8、本文 13px、補助 12px(フォントは Segoe UI Variable Text、無ければ Segoe UI)、

無効は不透明度 45%。

## 4. 部品(マニフェストの型との対応)

| 型 / 表示 | 部品 |
|---|---|
| `group` | 最上位はカード(見出し行で折りたたみ。閉じても要約を出せる)。入れ子は小見出し |
| `enum` (`presentation:"radio"` かつ 4 択以下) | セグメントボタン |
| `enum` (その他) | プルダウン(自前のポップアップ。8 件を超えるとスクロール) |
| `flags` | チップ(ON は淡い青地+チェック)。右上に All / None |
| `bool` | スイッチ(40 x 20) |
| `int` / `float` | スライダ(右に値)。`presentation:"knob"` はノブ(円弧の目盛+値) |
| `string` / `path` | テキスト欄(編集時のみ標準の入力欄を重ねる)。`path` は右に Browse… |
| `color` | 色見本+16 進欄。`palette` があれば見本の列 |
| `button` | ボタン(`confirm` があれば確認) |
| `readout` | ラベル+値(太字) |

キーボード: Tab / Shift+Tab で移動、Space / Enter で実行、左右でスライダ・ノブ・セグメント・チップを操作、Esc でポップアップを閉じる。

## 5. 実装構成

- `src/viewer/core/`(プラットフォーム非依存。Linux で単体テスト):
  `Theme`(配色)、`DrawList`(描画命令の列: 角丸矩形・楕円・線・円弧・文字・クリップ)、`TextMeasurer`(文字幅の抽象)、
  `PanelController`(マニフェスト+値からレイアウト・描画命令・入力への反応を生成する)。
- `src/viewer/win32/`: `ThemedPanel`(Direct2D で描画命令を実行し、マウス・キーを `PanelController` に渡す薄い層。
  文字入力・ファイル選択・色選択・確認は標準のダイアログ/入力欄を使う)。
- 描画命令に落とすことで、「選択中のセグメントがアクセント色で塗られる」「スライダのドラッグが値に変換される」
  といった見た目と操作の中身を、Windows なしでテストできる。
