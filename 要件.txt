あなたは熟練の Windows システムプログラマ兼 OpenGL グラフィックスエンジニアとして、
以下の仕様に基づく Windows スクリーンセーバー (.scr) を C++ で段階的に生成してください。

目的:
Windows デスクトップの実体（アイコン、開いているウィンドウ、背景画像）を段階的に吸い込む
アニメーションスクリーンセーバーを C++ + Win32 API + OpenGL を用いて実装する。
吸い込み中心は画面上をランダムに移動し、対象は中心に向かってらせん軌道で吸い込まれる。
最終的に黒背景になり、元の背景画像へフェードして初期状態に戻り、無限ループする。

────────────────────────────────────
【1. スクリーンセーバー仕様 (.scr)】
────────────────────────────────────
- Win32 API を使用してウィンドウを作成する。
- スクリーンセーバー引数に対応すること：
    /s → スクリーンセーバー開始
    /c → 設定ダイアログ（粒子数設定・背景画像設定を含む）
    /p → プレビュー（小さなウィンドウで描画）
- 出力は単一の .scr ファイルとしてビルド可能にする。
- フリーのコンパイラ（MinGW / MSVC Build Tools / Clang など）でビルド可能にするが、
  どのコンパイラを使うかは AI が最適に判断してよい。

────────────────────────────────────
【2. 描画環境】
────────────────────────────────────
- 初期実装は OpenGL 固定機能版（glBegin/glEnd）を基本とする。
- ただし、AI が必要と判断した場合は軽量なシェーダーを併用してもよい。
- ダブルバッファリングを有効にする。
- フレームレートは 60fps を目標とする。
- 解像度は現在のディスプレイ解像度を取得して使用する。

────────────────────────────────────
【3. デスクトップ要素の抽象化】
────────────────────────────────────
実際の Windows デスクトップを操作してはならない。
以下のように「模倣して描画する」抽象化を行う：

1. デスクトップアイコン  
    - 位置とラベルを持つ矩形として描画する。  
    - アイコン数は 20〜40 個程度のランダム生成でよい。

2. 開いているウィンドウ  
    - タイトルバー付きの矩形として描画する。  
    - ウィンドウ数は 5〜10 個程度のランダム生成でよい。

3. 背景画像  
    - デフォルトでは「Windows デスクトップで現在使用されている壁紙」を自動取得して使用する。  
    - 設定画面から任意の画像ファイルを指定して上書きできる。  
    - AI は壁紙取得方法を最適に判断してよい。

────────────────────────────────────
【4. 吸い込みアニメーション仕様】
────────────────────────────────────
吸い込み中心:
- 画面内をランダムウォークで移動する。
- 速度は一定（例: 1〜3px/frame）。

らせん軌道:
- 各オブジェクトは以下の式で中心へ向かう：
    θ += 0.15  
    r = 距離 - (吸い込み速度)  
    新しい位置 = center + (r * cos(θ), r * sin(θ))
- r が 0 になったらオブジェクトは消滅する。

吸い込みの順序:
1. アイコンをすべて吸い込む  
2. ウィンドウをすべて吸い込む  
3. 背景画像を NxN 粒子に分割し、粒子を吸い込む  
4. 完全に吸い込んだら画面を黒で塗りつぶす  
5. 黒背景 → 元の背景画像へフェードイン（alpha = 0 → 1）  
6. アイコンとウィンドウを元の位置に再描画  
7. ステップ1へ戻る（無限ループ）

────────────────────────────────────
【5. 粒子化仕様】
────────────────────────────────────
- 背景画像を NxN グリッドに分割し、各セルを粒子として扱う。
- 粒子数は設定画面で変更可能にする。
- 粒子はテクスチャの一部を描画してもよいし、単色でもよい。
- 粒子はらせん軌道で吸い込まれる。

────────────────────────────────────
【6. 粒子数設定（柔軟化済み）】
────────────────────────────────────
設定画面（/c）で粒子数を段階的に選択できる UI を実装する。

粒子数プリセット（例）:
- 低（1000粒子）
- 中（3000粒子）
- 高（6000粒子）
- 最高（12000粒子）
- 自動（GPU性能で決定）

※これらは例であり、AI は環境に応じてより適切な値を提案してもよい。

自動判定:
- glGetString(GL_VENDOR)
- glGetString(GL_RENDERER)
- glGetString(GL_VERSION)
を使用して GPU の種類を判定し、粒子数を自動設定する。

設定値の保存:
- レジストリではなく .ini ファイルに保存する。
- 例: %APPDATA%/SpiralSuctionSaver/config.ini

────────────────────────────────────
【7. 固定機能版での最適化】
────────────────────────────────────
固定機能版で粒子数を増やすため、以下を必ず実装する：

- glBegin/glEnd は粒子ごとに呼ばず、全粒子をまとめて描画する。
- 粒子サイズは固定にする。
- 色計算は CPU で行わない（固定色またはテクスチャ色）。
- らせん軌道の計算は軽量化する（θ += 0.1, r -= 0.5 など）。

────────────────────────────────────
【8. 状態管理】
────────────────────────────────────
以下の状態を持つステートマシンを実装する：

STATE_ICONS  
STATE_WINDOWS  
STATE_BACKGROUND  
STATE_BLACK  
STATE_FADE  
STATE_RESET  

update() と draw() のループで状態を進行させる。

────────────────────────────────────
【9. 出力形式】
────────────────────────────────────
以下の順番で段階的にコードを生成することを基本とするが、
AI は依存関係の都合で順序を調整してもよい。

Step 1: Win32 スクリーンセーバーの基本構造（/s /c /p の処理）  
Step 2: OpenGL 初期化コード（Win32 ウィンドウとの統合）  
Step 3: デスクトップ要素（アイコン・ウィンドウ）の抽象化描画  
Step 4: 吸い込み中心のランダム移動ロジック  
Step 5: らせん軌道の計算ロジック  
Step 6: 背景画像の粒子化処理（粒子数設定対応）  
Step 7: 黒背景 → フェードイン処理  
Step 8: 状態遷移のステートマシン  
Step 9: 設定画面（粒子数プリセット＋自動判定＋背景画像選択＋ini保存）  
Step 10: main.cpp（全体統合）  
Step 11: .scr としてビルド可能なプロジェクト構成  

────────────────────────────────────
【10. 禁止事項】
────────────────────────────────────
- 実際の Windows デスクトップアイコンを移動・削除してはならない。
- 実際のウィンドウを操作してはならない。
- OS の設定を変更してはならない。
- セキュリティ上の危険な API を使用してはならない。

以上の仕様に基づき、Step 1 から順にコードを生成してください。
